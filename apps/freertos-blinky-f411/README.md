# freertos-blinky-f411

FreeRTOS blinky on STM32F411 (WeAct BlackPill, LED PC13; UART log on PA9 at 115200 8N1).
Originally generated by the category's CLion helper (`mcu-ide new freertos ...`) from the example
`blinky-f411-freertos`; `../../toolchain/freertos` is never modified.

Everything here uses only this ID (`32_04_freertos`): Arm GNU toolchain, cmake, ninja, STM32CubeF4 and
FreeRTOS-Kernel from `../../toolchain/` (via `../../toolchain/freertos/env.sh`), output on idisk03 at the same ID path.

## Command line (from this folder)

```sh
../../scripts/app build . Debug       # or Release; -> <build>/freertos-blinky-f411.{elf,bin,hex}
../../scripts/app test .              # host unit tests (tests/, vendored GoogleTest, CTest)
../../scripts/app flash . Debug       # st-flash (default) | openocd | pyocd | probe-rs as 3rd argument
../../scripts/app monitor /dev/ttyUSB0 115200
```

| Profile | What it builds | Build dir |
|---|---|---|
| Debug | firmware | `$FREERTOS_OUT/apps/freertos-blinky-f411/cmake-build-debug` |
| Release | firmware | `$FREERTOS_OUT/apps/freertos-blinky-f411/cmake-build-release` |
| Host-Tests | `tests/` with the buildtools gcc + GoogleTest (CTest) | `$FREERTOS_OUT/apps/freertos-blinky-f411/cmake-build-host-tests` |

## CLion

File > Open > this folder. CLion reads `.idea/cmake.xml` (the three profiles above, same build dirs; each
profile's environment and CMake options point into this ID only). That file holds absolute paths of one machine, so it
is not in git: in a fresh clone create the profiles Debug/Release (toolchain file `cmake/arm-none-eabi.cmake`,
`-DCUBE=$STM32_CUBE_F4 -DFREERTOS_KERNEL=$FREERTOS_KERNEL`) and Host-Tests (`-DMCU_HOST_TESTS=ON`), with the environment
of `../../toolchain/freertos/env.sh`; or just use the `.run/` configurations, which call `scripts/app`.

Run configurations (`.run/`):

| Name | Does |
|---|---|
| Build | `../../scripts/app build . Debug` |
| Flash | `../../scripts/app build . Debug && ../../scripts/app flash . Debug` |
| Monitor | `../../scripts/app monitor` (edit the port in the script text) |
| Debug (OpenOCD + ST-Link) | starts this ID's xPack `openocd`, loads the ELF with CLion's bundled GDB |
| Host tests | runs `tests/` (select the Host-Tests profile first) |

## Files

- `CMakeLists.txt`: firmware build; the `MCU_HOST_TESTS` block at the top switches to the host tests.
- `cmake/`: toolchain file, `stm32f411.cmake`, HAL config, linker script, clock setup.
- `lib/ringbuf/`: target-independent code; `tests/test_ringbuf.cpp` tests it on the host. `tests/CMakeLists.txt`
  takes `McuHostTests.cmake` and GoogleTest from `../../toolchain/clion/`.
- `mcu-project.json`: settings for the category's `mcu-ide` helper, which also lists this app through a symlink
  in its own `projects/`. Do not regenerate this app with `mcu-ide new --force`: that would point the run
  configurations back at `mcu-ide`.
